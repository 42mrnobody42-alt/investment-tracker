## Contexto

Con la estructura de carpetas (TS-029), esta task crea `manifest.json` y el
script `gen-assets-manifest.mjs` que recorre el filesystem y genera el mapa
clave lógica → ruta física. El manifest es la única fuente de verdad para
`useAsset()` en runtime.

## Entregable

- `frontend/public/assets/manifest.json` con mapa clave → ruta (ej. `"logo.primary": "/assets/logos/logo-primary.svg"`).
- `frontend/scripts/gen-assets-manifest.mjs` que recorre `public/assets/` y regenera el manifest (idempotente).
- `frontend/package.json` script: `"assets:manifest": "node scripts/gen-assets-manifest.mjs"`.
- `frontend/tests/unit/scripts/gen-assets-manifest.test.ts` con 4 tests (manifest generado, idempotente, claves correctas, ruta con `assets/`).

## Criterios de aceptación

- [ ] **CA_01:** `frontend/public/assets/manifest.json` con al menos: `logo.primary`, `logo.primary.dark`, `logo.compact`, `logo.partner.placeholder`, `image.initPage.hero`, `icon.common.arrowRight`, `icon.common.close`, `icon.common.menu`.
- [ ] **CA_02:** `node scripts/gen-assets-manifest.mjs` regenera el manifest idéntico (idempotente).
- [ ] **CA_03:** Claves en `camelCase` con dot notation (`<tipo>.<dominio>.<nombre>`).
- [ ] **CA_04:** Path en el manifest empieza con `/assets/` (URL estable).
- [ ] **CA_05:** `npm run assets:manifest` en `package.json`.
- [ ] **CA_06:** `frontend/tests/unit/scripts/gen-assets-manifest.test.ts` con 4 tests.
- [ ] **CA_07:** `Frontend-test-Dev.sh` verde con assets-manifest incluido.
