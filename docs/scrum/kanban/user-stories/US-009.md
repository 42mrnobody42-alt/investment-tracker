## Resumen ejecutivo

**Qué resuelve**: sirve logos, imágenes, iconos y fuentes desde `public/assets/`
con resolución runtime vía `manifest.json` + `useAsset()`. Los assets de
branding se pueden reemplazar post-deploy sin rebuild del bundle.

**Resultado observable**: `useAsset('logo.primary')` devuelve la URL correcta
en runtime; reemplazar un logo en `public/assets/logos/` se refleja sin
rebuild; `useAsset('inexistente')` devuelve un placeholder + `console.warn`
(no rompe la vista); Inter + JetBrains Mono self-hosted con `font-display: swap`.

## Contexto

Los logos e imágenes corporativas hoy se importan por bundler (hash + rebuild
obligatorio). El branding mutable es requisito del proyecto (reemplazo sin
rebuild). Fuentes self-hosted (TS-011) ya existen pero las de branding todavía
se cargan desde `branding/tipografia.css`.

## Alcance

- **Estructura**: `frontend/public/assets/{logos,images,icons,fonts}/` con subcarpetas por dominio (`images/initPage/`, `images/login/`, `icons/common/`, `icons/admin/`, etc.).
- **Manifest**: `public/assets/manifest.json` generado por `gen-assets-manifest.mjs` (recorre filesystem + genera mapa clave lógica → ruta física).
- **Hook**: `useAsset('clave')` resuelve la URL en runtime (fetch manifest).
- **URL estable**: sin hash (rollback via manifest).
- **Fallback**: placeholder + `console.warn` si la clave no existe (no rompe la vista).
- **Fuentes**: Inter + JetBrains Mono self-hosted con `font-display: swap` + preload del subset crítico.

**Fuera del scope**:

- CDN externo.
- Optimización AVIF/WebP (diferida a task futura).
- Cache-busting con hash (URL estable elegida).
